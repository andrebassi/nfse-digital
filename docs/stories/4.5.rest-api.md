## Story

As a dono do emissor, I want que meu ERP/faturamento emita, liste, consulte e cancele notas por HTTP, so that a fatura gerada lá vire NFS-e sem passar por agente nem pelo painel — no mesmo formato que o SaaS usado antes oferece (aba "API REST" em Integrações, documentação Scalar, OpenAPI e llms.txt).

## Acceptance Criteria

1. `/api/v1` com `account`, `customers`, `templates`, `invoices` (listar/emitir), `invoices/{id}`, `invoices/by-key?idempotency_key=`, `invoices/{id}/cancel`, `invoices/{id}/danfse`, autenticado pelo mesmo token Bearer do MCP e preso à conta do token.
2. Emissão exige `idempotency_key`; repetir a chave devolve a mesma nota (200) e não cria outra; nota nova é 201 com `Location`; SEFIN sem resposta é 202.
3. Produção exige `confirm_production: true` (409 sem ela, nada sai para a SEFIN); campo desconhecido no JSON é 400.
4. Erros sempre em JSON (`error`, `fields`, `invoice`), com a tabela de status do contrato.
5. `/api/v1/openapi.json` (OpenAPI 3.1) descreve exatamente as rotas registradas — teste nos dois sentidos.
6. `/api/docs` renderiza o contrato com Scalar vendorizado (sem CDN), CSP só com script local, sem barra de desenvolvedor, "Ask AI" nem telemetria.
7. `/api/llms.txt` com URLs absolutas do painel que o serve.
8. Aba "API REST" em Integrações: URL base, autenticação, exemplos (Emitir, Consultar, Listar, Cancelar) com o tomador e o modelo da conta, Copiar, Gerar token que volta com o token nos exemplos, links para documentação, OpenAPI e llms.txt.
