## Story

As a dono do emissor, I want emitente, tomadores, modelos, notas e agendamentos em SQLite, so that o histórico e a numeração sobrevivam entre execuções.

## Acceptance Criteria

1. Port `Repository` com métodos para cada entidade e `ReserveDPSNumber(ctx, env) (series, number, error)` atômico.
2. Migrações embutidas (`go:embed`) aplicadas na abertura, com tabela de versão.
3. Schema igual ao DDL abaixo, com `UNIQUE (environment, series, dps_number)`.
4. Reservar número incrementa `next_number` e insere a nota `pending` na mesma transação.
5. Duas reservas concorrentes nunca devolvem o mesmo número (teste com goroutines).
6. Banco padrão em `~/.local/share/nfse/nfse.db`, sobrescrevível por `NFSE_DB`.

## Dev Notes

Driver `modernc.org/sqlite` (sem CGO). `PRAGMA foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout=5000`.

```sql
CREATE TABLE issuer (id INTEGER PRIMARY KEY CHECK (id = 1), cnpj TEXT NOT NULL, legal_name TEXT NOT NULL,
  municipal_registration TEXT, city_code TEXT NOT NULL, simples_option INTEGER NOT NULL, simples_regime INTEGER,
  special_regime INTEGER NOT NULL DEFAULT 0,
  environment TEXT NOT NULL DEFAULT 'homologation' CHECK (environment IN ('homologation','production')),
  series TEXT NOT NULL DEFAULT '1', next_number INTEGER NOT NULL DEFAULT 1);
CREATE TABLE customers (id INTEGER PRIMARY KEY, document TEXT NOT NULL UNIQUE, name TEXT NOT NULL, email TEXT,
  street TEXT, number TEXT, district TEXT, city_code TEXT, zip TEXT);
CREATE TABLE templates (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE, national_tax_code TEXT NOT NULL,
  municipal_tax_code TEXT, description TEXT NOT NULL, iss_rate_bp INTEGER NOT NULL,
  default_customer_id INTEGER REFERENCES customers(id));
CREATE TABLE invoices (id INTEGER PRIMARY KEY, environment TEXT NOT NULL, series TEXT NOT NULL,
  dps_number INTEGER NOT NULL, dps_id TEXT NOT NULL, customer_id INTEGER NOT NULL REFERENCES customers(id),
  template_id INTEGER REFERENCES templates(id), amount_cents INTEGER NOT NULL, competence_date TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('pending','authorized','rejected','cancelled')),
  access_key TEXT, nfse_number TEXT, error_code TEXT, error_message TEXT, sent_xml TEXT, response_body TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL, UNIQUE (environment, series, dps_number));
CREATE TABLE schedules (id INTEGER PRIMARY KEY, template_id INTEGER NOT NULL REFERENCES templates(id),
  customer_id INTEGER NOT NULL REFERENCES customers(id), amount_cents INTEGER NOT NULL,
  day_of_month INTEGER NOT NULL CHECK (day_of_month BETWEEN 1 AND 28), active INTEGER NOT NULL DEFAULT 1,
  last_run_period TEXT);
```

- Numeração continua de onde o SaaS usado antes parou: a nota rejeitada usou série 1 / DPS 202628; o `next_number` inicial é configurável (`nfse settings --next-number`).
