## Story

As a dono do emissor, I want importar o XML de uma NFS-e já emitida, so that emitente, tomador e serviço virem cadastro e a próxima nota peça só valor e competência.

## Acceptance Criteria

1. `nfse import <arquivo.xml> --template-name <nome>` lê NFS-e nacional (XML autorizado) e DPS.
2. Cria ou atualiza: emitente (se vazio), tomador (por documento), modelo (cTribNac, descrição, alíquota).
3. Não sobrescreve emitente já configurado sem `--overwrite-issuer`.
4. Relatório do que foi criado, atualizado e ignorado.
5. XML malformado ou de outro layout → erro claro, sem gravação parcial (transação).
6. `nfse import --portal` consulta, só leitura, as NFS-e já emitidas pelo CNPJ no ambiente nacional (ADN) com o A1, e mostra o progresso por etapa: certificado validado, conexão mTLS, notas lidas, modelos gerados.
7. As notas encontradas são agrupadas por serviço recorrente (tomador + cTribNac + descrição): cada grupo mostra quantas notas, frequência (`todo mês` ou `esporádico`), valor da última e se já está cadastrado.
8. O dono escolhe quais grupos viram modelo (nada é gravado antes da escolha); o tomador de cada grupo é importado junto.
9. A importação também preenche série, próximo número da DPS e data da última nota.

### Completion Notes

- `nfse import <arquivo>` e tela "Importar de um XML" (upload, limite de 2 MB no middleware, 413 acima disso). XML real da nota 38 importado num banco temporário; segunda importação não duplica (tomador e modelo atualizados, nota "já existia").
- `internal/adapters/nfsexml`: lê NFS-e e DPS nos dois leiautes (IBS/CBS aninhado ou direto) e eventos de cancelamento (e101101, e105102), formato conferido no XML real.
- Importação pelo Portal: `nfse import --portal --production [--apply all|grupos]` lê a distribuição do ADN (`GET /contribuintes/DFe/{NSU}`, só leitura, com o A1), separa as notas EMITIDAS das recebidas, aplica cancelamentos e agrupa por tomador + código de serviço. Medido em 30/10/2026: 25 emitidas, 2 canceladas (= as 23 ativas do SaaS usado antes), 22 em que o CNPJ é tomador; 8 grupos. Aplicado num banco temporário: 25 importadas, reaplicar importa 0.
- Três achados de transporte, todos travados em teste: o ADN pede o certificado em TLS 1.2 com lista de ACs que não casa com a cadeia do .pfx (resolvido com `GetClientCertificate`); em TLS 1.3 o pedido vem pós-handshake, que o Go não suporta (leitor fixo em TLS 1.2); a SEFIN redireciona rota errada para http (leitor não segue redirecionamento).
- Desvios: a tela do Portal (escolha de grupos no painel) ficou para a story 4.3 — a escolha existe na CLI (`--apply`). O agrupamento é por tomador + código de serviço (8 grupos), mais fino que os 5 do SaaS usado antes. Sem transação entre as gravações de uma importação (o port não expõe transação); erro de leitura do XML acontece antes de qualquer gravação.
